AgentPay · 链上按次计费

让 AI Agent 自己付钱 Per-call Payments, On-chain

AgentPay 是跑在 BNB Smart Chain 上的 AI Agent 微支付基础设施： 每个 agent 调用付一次钱，链上托管结算，付了没交付可以退款，扯皮可以仲裁。

What is AgentPay

为高频微支付而生的结算层

以太坊做不到的，BSC 可以：gas 低到单笔调用几分钱也划得来。AgentPay 把"按次付费"变成可验证的链上事实。

托管结算 Escrow

付款进合约托管，服务方交付成功才 claim() 结算；超时未交付，付款方可 refund() 原路退回。

链上仲裁 Arbitration

交付有争议？付款方 dispute() 冻结托管，独立仲裁人 resolve() 裁决归谁，资金不会烂在合约里。

零沉淀 Zero Balance

结算/退款/裁决后合约余额恒为 0，没有可被攻击的资金池；0.5% 平台费在 Paid 事件里永远可查。

请求与付款绑定

challenge + EIP-712 签名：一笔付款只服务一次请求，换 prompt、换客户端、换私钥全部失效。

真实推理接口

网关接 OpenAI 兼容接口（LLM_BASE_URL），计费逻辑与模型无关；没配模型自动回退 mock。

可扩展部署

challenge 状态可落 sqlite / redis，多实例共享；HTTPS + mTLS 强制传输安全。

How it works

一次付费调用的完整旅程

agent 遇到 402 自动完成付款，人类无需介入。

1. 请求

agent 调用 POST /v1/infer，网关返回 402 + 一次性 challenge（含请求指纹与过期时间）。

2. 付款

agent 调用合约 pay(serviceId, calls, challengeId)，资金进托管，challengeId 写入链上 memo。

3. 签名

agent 用 EIP-712 对同一个 challengeId 签名，声明"这笔付款是我付的"。

4. 核验

网关校验：challenge 未用未过期、客户端身份一致、请求指纹一致、签名者等于链上付款人。

5. 交付+结算

返回结果，服务方 claim() 结算（99.5% 归服务方，0.5% 进财库）。合约余额归零。
