快速开始（本地，无需真实资产）

仓库在 agentpay/，Node ≥ 20（内部用 node:sqlite）。

npm install
npm run certs                      # 生成本地 TLS/mTLS 证书
npx hardhat test                   # 59 passing

# 终端 A：本地链
npx hardhat node

# 终端 B：部署 + 注册 + 网关
npx hardhat run scripts/deploy.js --network localhost
npx hardhat run scripts/register-service.js --network localhost
$env:STORE="redis"; $env:REDIS_URL="redis://127.0.0.1:6379"
$env:REQUIRE_TLS="1"; $env:TLS_CERT="certs/server.crt"; $env:TLS_KEY="certs/server.key"
$env:PROVIDER_PRIVATE_KEY="<服务方钱包私钥>"
node demo/server.js

# 终端 C：全攻击面演示 + 仲裁 + 退款
$env:ENDPOINT="https://127.0.0.1:4021/v1/infer"
node demo/client.js "为什么 BSC 适合做 agent 微支付"
node demo/dispute.js
node demo/refund.js                # 最后跑，会拨快本地链时间

本地链会自动给前 3 个测试账户各发 10000 AGP，方便直接跑 demo。更多细节见仓库 README。

架构

agent (SDK) ──HTTPS/mTLS──► 网关 demo/server.js ──► BSC (RPC)
      │                            │                      │
      │  402 + challenge           │  签发一次性 challenge │
      │◄───────────────────────────┘                      │
      │   pay(serviceId, calls, challengeId) ────────────► │  资金进 escrow
      │   EIP-712 签名                                     │
      │  POST + X-PAYMENT-TX/-CHALLENGE/-SIGNATURE ──────► │
      │                            │  校验五层防线          │
      │◄── 200 + 结果 ─────────────┘  claim() 结算 ◄───────┤
      │
      store: memory / sqlite / redis   （challenge 状态，多实例共享）

SDK 接入（在你的 agent 里）

一行搞定 402 → 付款 → 签名 → 重试，不需要 agent 处理协议细节：

const { AgentPayClient } = require("agentpay/sdk/agentpay-client");

const client = new AgentPayClient({
  rpcUrl: "https://bsc-dataseed.bnbchain.org",
  privateKey: process.env.AGENT_KEY,          // agent 自己的钱包
  token: "0x…",                               // AGP
  agentPay: "0x…",                            // AgentPay 合约
  tls: { ca, cert, key },                     // mTLS 客户端证书（可选）
});

const res = await client.fetchPaid("https://api.vaultra/v1/infer", "你的 prompt");
console.log(res.body.output);
console.log(res.payment.txHash);              // 链上收据
console.log(res.body.billing.settlement);     // claimed / pending / manual

SDK 内部处理：402 解析、challenge 重算、EIP-712 签名、allowance 授权、NonceManager 防撞 nonce、重试。

合约 API

函数谁可调作用
setService(id, price, endpoint)服务方注册/更新服务定价与接口
closeService(id)该服务方下线服务，停止新付款
pay(id, calls, memo)任何人按次预付，资金进 escrow，memo 即托管 key
claim(memo)该服务 provider交付后结算：net 给服务方，fee 进财库
refund(memo)原付款人超时未结算，原额退回
dispute(memo)原付款人结算前发起争议，托管冻结
resolve(memo, toProvider)仲裁人裁决：判服务方按 claim 分配，判付款方原额退回
setFee / setRefundDelay / setTreasury / setArbiterowner费率（≤5%）、退款窗口（1h–30d）、财库、仲裁人

状态机：OPEN → CLAIMED / REFUNDED / DISPUTED → RESOLVED。事件：Paid / Claimed / Refunded / Disputed / Resolved，全部带 memo 与金额，可离线审计。

部署指南

  1. 领测试币：BNB Chain Faucet（0.3 tBNB/天，主网地址需 ≥0.002 BNB 防机器人）
  2. cp .env.example .env，填 PRIVATE_KEY（专用测试钱包）
  3. npm run deploy:testnet 与 npm run register:testnet
  4. BscScan 验证源码（部署脚本会打印 verify 命令）
  5. 主网同样流程，deploy:mainnet；部署 gas 约 150 万单位，通常 $0.05–$0.30
上线前必做：BscScan 验证源码；建 PancakeSwap V2 池并锁 LP；setRefundDelay() 调业务窗口；财库与仲裁人换成多签；第三方审计。

服务商接入

你只需要三样东西：一个部署了 AgentPay 的合约地址、一个自己的钱包（provider）、一个后端推理接口。

  1. 跑网关：node demo/server.js，配 PROVIDER_PRIVATE_KEY 后交付自动 claim()
  2. 去 服务商后台（需要后台服务已启动）查看服务、托管、账单与争议
  3. 收款直接到你的钱包，0.5% 平台费在链上事件里可查

安全模型

五层防线全部实测：challenge 一次性 + 过期（默认 120s）、请求指纹绑定、EIP-712 签名者 == 链上付款人、客户端身份绑定（mTLS / IP+UA）、escrow 托管 + 仲裁。传输层强制 HTTPS，可选 mTLS 客户端证书。

已知边界：仲裁是单点信任（一个仲裁地址），生产建议多签仲裁团；DISPUTED 无链上时限，业务层要约定仲裁期限；服务方自动 claim 的私钥在生产环境应放 KMS。

FAQ

  • 为什么选 BSC 而不是以太坊？ gas 便宜 50–100 倍，单笔调用几分钱才划得来，这是微支付的物理前提。
  • 一次付款能用几次？ 一次。challenge 单次核销，换 prompt / 换客户端 / 重放全部拒绝。
  • 付款了但服务没交付？ 超时 refund() 原路退回；有争议走 dispute() → 仲裁。
  • 服务方要交押金吗？ 不需要。钱只在托管期由合约保管，结算后归零。
  • 平台费多少？ 0.5%（可配，硬上限 5%），链上事件可查，owner 改费率也受上限约束。
  • 能接自己的模型吗？ 能。网关 LLM_BASE_URL 指向任意 OpenAI 兼容接口即可，计费逻辑不变。
  • 合约安全吗？ 59 个测试覆盖，但未经第三方审计，主网前务必审计。
